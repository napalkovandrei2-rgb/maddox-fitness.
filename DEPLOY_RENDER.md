# Публикация MADDOX на Render

## Что важно знать до публикации

- Бесплатный адрес Render будет иметь вид `https://maddox-fitness.onrender.com` (если имя свободно).
- Текущий проект использует SQLite. Чтобы заявки не терялись после перезапуска/деплоя, `render.yaml` настроен на платный Web Service `starter` и постоянный диск `1 GB`.
- Бесплатный Web Service не поддерживает постоянные диски, а его файловая система очищается при перезапусках/деплоях. Поэтому текущий SQLite-проект нельзя безопасно запускать на бесплатном тарифе для реальных заявок.
- На странице Render тариф `Starter` указан от $7/месяц; постоянный диск оплачивается отдельно. Проверьте актуальную цену перед подтверждением.
- Сам домен `onrender.com` бесплатный. Это не означает, что вычислительный сервер и постоянное хранилище бесплатные.

## 1. Создайте GitHub-репозиторий

1. Войдите в GitHub и создайте новый пустой репозиторий, например `maddox-fitness`.
2. Распакуйте архив проекта.
3. Загрузите в репозиторий содержимое папки `maddox_fitness_site` (файлы `package.json`, `server.js`, папки `public/`, `assets/`, `render.yaml` и т. д.). Не загружайте `node_modules`, `.env` или файлы базы данных.
4. Убедитесь, что `render.yaml` находится в корне репозитория.

## 2. Создайте сервис через Blueprint

1. Откройте https://dashboard.render.com/blueprints.
2. Нажмите **New Blueprint Instance**.
3. Подключите GitHub, выберите репозиторий `maddox-fitness`.
4. Render прочитает `render.yaml`. Проверьте имя `maddox-fitness`, план `Starter` и диск `1 GB`.
5. Подтвердите создание сервиса. Выберите подходящий регион, предпочтительно Frankfurt, если он доступен для вашего аккаунта.
6. Дождитесь статуса **Live**. Адрес сайта будет указан на странице сервиса в Render.

## 3. Секреты и почтовые уведомления

В настройках сервиса → **Environment** задайте значения:

- `ADMIN_TOKEN` — длинный случайный секрет (не публикуйте его и не отправляйте посетителям сайта).
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` — параметры почтового провайдера.
- `MAIL_FROM` — разрешённый адрес отправителя у почтового провайдера.
- `NOTIFY_EMAIL` — адрес администрации, куда отправлять новые заявки.

После изменения переменных выполните **Save, rebuild, and deploy**. Не вставляйте секреты в исходный код или GitHub.

Если SMTP пока не настроен, форма всё равно сохранит заявку в базе, но письмо администратору не отправится. Уведомления можно подключить позднее.

## 4. Панель администратора

Откройте `https://ВАШ-СЕРВИС.onrender.com/admin`, введите `ADMIN_TOKEN` из Environment и нажмите «Загрузить заявки». Не передавайте токен третьим лицам.

## 5. Проверка

1. Откройте `/api/health` — должен вернуться JSON с `ok: true`.
2. Отправьте тестовую заявку с собственными тестовыми контактами.
3. Убедитесь, что заявка появилась в `/admin`.
4. Перезапустите сервис и проверьте, что заявка сохранилась на постоянном диске.
5. Проверьте получение письма, если SMTP уже настроен.

## 6. Перед приёмом реальных заявок

Заполните placeholders в `terms.html`, `privacy.html`, `consent.html` реальными реквизитами оператора, контактами и сведениями о фактической обработке данных. Проверьте тексты с юристом/ответственным за персональные данные. Настройте ограниченный доступ к Render и резервное копирование базы.

В текущем проекте нет SMS-кода подтверждения телефона и автоматической отправки рекламных писем. Чекбокс рекламы отдельный и необязательный; значение согласия сохраняется вместе с заявкой.
