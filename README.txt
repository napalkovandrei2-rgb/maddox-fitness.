MADDOX FITNESS — сайт + сервер регистрации

ЗАПУСК ЛОКАЛЬНО
1. Установите Node.js 20 или новее.
2. Откройте терминал в папке сайта.
3. Выполните: npm install
4. Скопируйте .env.example в .env и заполните ADMIN_TOKEN.
5. Для уведомлений заполните SMTP_HOST, SMTP_USER, SMTP_PASS, NOTIFY_EMAIL и MAIL_FROM.
6. Запустите: npm start
7. Откройте http://localhost:3000

Файлы публичной части расположены в папке public/.

ЗАЯВКИ И АДМИНИСТРИРОВАНИЕ
- POST /api/applications — проверяет данные и обязательное согласие, сохраняет заявку в SQLite.
- GET /api/admin/applications — список заявок, заголовок Authorization: Bearer ADMIN_TOKEN.
- PATCH /api/admin/applications/:id — меняет статус (new/contacted/closed).
- /admin — простая закрытая токеном страница администратора.
- База находится в DATA_DIR/maddox.sqlite. На облачном хостинге нужен постоянный диск.
- Уведомление по SMTP отправляется администратору после сохранения заявки. Если SMTP не настроен, заявка всё равно сохраняется, но письмо не уйдёт.

РАЗВЁРТЫВАНИЕ
В комплекте есть render.yaml для Render. Создайте новый Blueprint из репозитория с этими файлами, подключите постоянный диск и заполните SMTP-переменные в настройках сервиса. Не публикуйте .env и не передавайте ADMIN_TOKEN посторонним. Если используете другой хостинг, задайте Node 20+, npm install, npm start, постоянный каталог DATA_DIR и переменные окружения.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- Реальная отправка SMS/подтверждение номера пока не подключена: для неё нужен выбранный SMS-провайдер и его API-ключ. Сейчас номер валидируется по формату, но не подтверждается кодом.
- Форма не добавляет пользователя автоматически в рекламную рассылку. Поле рекламного согласия сохраняется отдельно; для реальной рассылки нужен сервис рассылок и механизм отписки.
- До приёма реальных персональных данных заполните реквизиты оператора в terms.html, privacy.html и consent.html, настройте законное хранение/доступ, проверьте применимость требований законодательства и политику резервного копирования с юристом/ответственным за ПДн.
- База SQLite содержит персональные данные. Ограничьте доступ к серверу и резервным копиям, используйте HTTPS и не включайте логи с содержимым заявок.
- Пользовательский интерфейс может быть доступен из браузера только после размещения на сервере. Открытие index.html двойным щелчком не запустит API.

ПУБЛИКАЦИЯ НА RENDER
Подробная инструкция: DEPLOY_RENDER.md. Бесплатный адрес onrender.com доступен, но текущая конфигурация использует платный Starter и постоянный диск, потому что бесплатная файловая система Render очищается при перезапуске. Не переводите текущий SQLite-проект на Free, если собираетесь принимать реальные заявки.
